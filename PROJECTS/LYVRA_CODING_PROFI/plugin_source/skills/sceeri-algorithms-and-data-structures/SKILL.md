# Algorithms and Data Structures
Use only when algorithm selection, implementation or complexity is involved.
1. State inputs, outputs, constraints, limits and intended environment. Confirm data size and performance budget.
2. Trace a small case and establish baseline/brute-force complexity.
3. Choose algorithm by invariants and evidence, not keyword matching alone: binary search/two pointers for ordered sequences, sliding windows for bounded contiguous ranges, hash maps for average constant-time lookup, heaps for top-k, monotone stacks for nearest greater, BFS for unweighted shortest paths, Dijkstra for nonnegative weighted paths, DFS/backtracking for exploration, DP for overlapping subproblems, union-find for component connectivity, tries for prefixes.
4. Explain correctness: invariant or exchange argument; for DP define state, transition and base cases; for greedy prove local choice is safe.
5. Implement complete code with edge cases, deterministic tests, boundaries, adversarial inputs and performance checks when feasible.
6. State worst-case and expected time/space separately; distinguish amortized and auxiliary space where relevant. Hash tables have O(1) expected lookup, not guaranteed worst-case.
7. Follow existing public interfaces and preserve behavior unless explicitly asked to change it.
No project mutation without authorization. Mark unexecuted tests OPEN.
