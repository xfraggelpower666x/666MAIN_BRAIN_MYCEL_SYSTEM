# Sprach- und Plattformprofile

Beginne mit belegter Zielversion, Build-Werkzeug, Codekonvention und bestehenden Schnittstellen. Nutze die passende Zeile als Prüfschwerpunkt.

| Profil | Worauf prüfen |
| --- | --- |
| Modernes C++ | RAII, Ownership, Lebensdauer von Views, Grenzen von Ranges, geeignete Fehlerrepräsentation und Build-Kompatibilität |
| Unreal C++ | UObject-Lebenszyklus, Reflection, Komponenten, Game-Thread, Replikationszuständigkeit und Modulabhängigkeiten |
| C# und .NET | Nullable-Verträge, unveränderliche Daten, Async-Abbruch, Ressourcenfreigabe, DI-Lebensdauer und Tests |
| PHP | Typen, Composer-/PSR-Konventionen, Eingabegrenzen, Fehlerübersetzung, Transaktionen und Ressourcen |
| SQL | Dialekt, Parameterbindung, Schlüssel und Constraints, Isolation, Datenmigration, Indizes und beobachteten Abfrageplan |
| Node.js und TypeScript | Modulformat, externe Eingaben zur Laufzeit validieren, begrenzte Nebenläufigkeit, Streams, Zeitlimits und sauberes Beenden |
| Firebase-Funktionen | Ereignis-ID, Idempotenz, Wiederholungen, Secrets, Initialisierung und lokale Emulator- oder Fixture-Tests |

Verwende [Java](../sceeri-java-engineer/SKILL.md), [Python](../sceeri-python-engineer/SKILL.md) und [Web](../sceeri-web-engineer/SKILL.md) für diese Plattformen. Nutze Sprachmerkmale nur, wenn das Ziel sie unterstützt. Behandle Promptbeispiele und Stilregeln der Quellen als Vorschläge, die an das Zielprojekt angepasst werden.
